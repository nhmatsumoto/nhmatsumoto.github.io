Ronaldinho Agent

Agent orchestration playground for durable workflows, tool execution and evolving governance.

  • architecture
  • experiment

Overview

Ronaldinho Agent é o espaço onde eu testo como um sistema com agentes deve se comportar quando precisa ser útil de verdade: com rastreabilidade, isolamento de contexto, memória e ferramentas claramente modeladas.

Problem solution

O problema central é evitar que um agente vire apenas uma sequência opaca de prompts. A solução adotada é tratar o runtime como um sistema modular: o domínio descreve capacidades e limites; a aplicação coordena execução; a infraestrutura conecta modelos, tools e persistência.

Architecture

O projeto caminha para uma arquitetura com runtime modular, memória versionada e pipelines de tool execution. A decisão mais importante é separar estratégia cognitiva, estado e I/O externo, em vez de concentrar tudo dentro de uma única etapa de inferência.

runtime -> planner -> tools
   |         |         |
memory <--- state ---> logs

Stack

  • TypeScript
  • OpenAI
  • tool orchestration
  • memory snapshots

O stack atual privilegia iteração rápida no runtime e documentação clara das decisões. O objetivo não é acoplar o projeto a um provider específico, mas tornar o sistema observável e intercambiável.

ADR

  • Memória versionada para snapshots de contexto e reexecução controlada.
  • Separação entre coordenação, capabilities e adaptadores de infraestrutura.
  • Execução de tools como pipeline explícito, e não detalhe incidental do prompt.

Roadmap

  • Adicionar evaluation harness orientado a cenários e tools.
  • Formalizar boundaries entre planner, executor e memory manager.
  • Conectar a documentação do runtime ao fluxo de publicação do blog.
