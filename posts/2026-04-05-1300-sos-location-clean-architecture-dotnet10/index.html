SOS Location: Clean Architecture + CQRS em .NET 10

Arquitetura limpa, CQRS com MediatR e domain events no backend do SOS Location. Como estruturamos o código para resiliência em cenários de crise.

Clean Architecture + CQRS no backend do SOS Location

Em Abril de 2026, o commit refactor: migrate all page components to the domains/operations directory marcou a conclusão de uma refatoração profunda do backend do SOS Location. Não foi só reorganizar pastas — foi repensar como o código deveria crescer quando vidas dependem da sua corretude.

Por que Clean Architecture num sistema de desastres?

Sistemas de resposta a catástrofes têm um perfil incomum:

  1. Picos imprevisíveis — Um terremoto de magnitude 7 pode gerar 10x o tráfego normal em segundos
  2. Múltiplos agentes de entrada — APIs externas, agentes CLI (Codex), SignalR, CRON jobs
  3. Auditoria obrigatória — Cada mutação de estado precisa de trace_id, actor e reason
  4. Evolução constante — Fase 8, 9, 10... o sistema cresce com o projeto

Clean Architecture separa essas preocupações em camadas com dependências unidirecionais:

TEXT
Domain         → apenas lógica de negócio, sem imports de infraestrutura
Application    → casos de uso (Commands, Queries, Handlers)
Infrastructure → EF Core, PostGIS, SignalR, Keycloak
Presentation   → ASP.NET Core Controllers, Minimal API

CQRS com MediatR

O padrão CQRS (Command Query Responsibility Segregation) separa operações de escrita (Commands) de leitura (Queries).

Command: criar incidente

C#
// Application/Commands/CreateIncidentCommand.cs
public record CreateIncidentCommand(
    string EventId,
    IncidentType Type,
    int Severity,
    GeoJsonGeometry Location,
    DateTimeOffset OccurredAt,
    string ActorId
) : IRequest<Result<IncidentDto>>;

public class CreateIncidentHandler : IRequestHandler<CreateIncidentCommand, Result<IncidentDto>>
{
    private readonly IIncidentRepository _incidents;
    private readonly IEventBus _eventBus;
    private readonly IAuditLog _audit;

    public async Task<Result<IncidentDto>> Handle(
        CreateIncidentCommand cmd, CancellationToken ct)
    {
        // Domain validation
        if (cmd.Severity < 1 || cmd.Severity > 10)
            return Result.Fail("Severity must be between 1 and 10");

        var incident = Incident.Create(
            cmd.EventId, cmd.Type, cmd.Severity,
            cmd.Location, cmd.OccurredAt);

        await _incidents.AddAsync(incident, ct);

        // Audit trail — sempre
        await _audit.RecordAsync(new AuditEntry(
            Actor:   cmd.ActorId,
            Action:  "incident.created",
            TraceId: Activity.Current?.TraceId.ToString() ?? Guid.NewGuid().ToString(),
            Payload: JsonSerializer.Serialize(incident)
        ), ct);

        // Domain event: notifica SignalR, ML, operações críticas
        if (incident.Severity >= 7)
            _eventBus.Publish(new CriticalIncidentCreated(incident));

        return Result.Ok(incident.ToDto());
    }
}

Query: busca espacial com PostGIS

C#
// Application/Queries/GetIncidentsInRadiusQuery.cs
public record GetIncidentsInRadiusQuery(
    double Lat, double Lon, double RadiusKm
) : IRequest<IReadOnlyList<IncidentDto>>;

public class GetIncidentsInRadiusHandler
    : IRequestHandler<GetIncidentsInRadiusQuery, IReadOnlyList<IncidentDto>>
{
    private readonly SosDbContext _db;

    public async Task<IReadOnlyList<IncidentDto>> Handle(
        GetIncidentsInRadiusQuery q, CancellationToken ct)
    {
        var point = new Point(q.Lon, q.Lat) { SRID = 4326 };
        double radiusMeters = q.RadiusKm * 1000;

        return await _db.Incidents
            .Where(i => i.Location.IsWithinDistance(point, radiusMeters))
            .OrderByDescending(i => i.Severity)
            .ThenByDescending(i => i.OccurredAt)
            .Select(i => i.ToDto())
            .ToListAsync(ct);
    }
}

Domain Events para operações críticas

O domínio publica eventos sem saber quem os consome. A infraestrutura conecta:

C#
// Domain/Events/CriticalIncidentCreated.cs
public record CriticalIncidentCreated(Incident Incident) : IDomainEvent;

// Infrastructure/EventHandlers/NotifyOpsOnCriticalIncident.cs
public class NotifyOpsOnCriticalIncident
    : INotificationHandler<CriticalIncidentCreated>
{
    private readonly IHubContext<OpsHub> _hub;
    private readonly IRiskModelClient _riskModel;

    public async Task Handle(CriticalIncidentCreated e, CancellationToken ct)
    {
        // 1. Notifica o dashboard em tempo real via SignalR
        await _hub.Clients.Group("ops-commanders")
            .SendAsync("IncidentAlert", e.Incident.ToAlertPayload(), ct);

        // 2. Solicita análise de risco ao ML Unit (async)
        await _riskModel.RequestAnalysisAsync(e.Incident.Location, ct);
    }
}

Pipeline de comportamentos transversais

MediatR permite adicionar behaviors que se aplicam a todos os Commands/Queries — como logging, validação e retry:

C#
// Registrado no DI antes de todos os handlers
services.AddTransient(typeof(IPipelineBehavior<,>), typeof(ValidationBehavior<,>));
services.AddTransient(typeof(IPipelineBehavior<,>), typeof(LoggingBehavior<,>));
services.AddTransient(typeof(IPipelineBehavior<,>), typeof(DistributedTracingBehavior<,>));

// LoggingBehavior.cs
public class LoggingBehavior<TRequest, TResponse>
    : IPipelineBehavior<TRequest, TResponse>
{
    private readonly ILogger<TRequest> _logger;

    public async Task<TResponse> Handle(
        TRequest req, RequestHandlerDelegate<TResponse> next, CancellationToken ct)
    {
        var sw = Stopwatch.StartNew();
        _logger.LogInformation("Handling {Request}", typeof(TRequest).Name);
        var response = await next();
        _logger.LogInformation("Handled {Request} in {Elapsed}ms",
            typeof(TRequest).Name, sw.ElapsedMilliseconds);
        return response;
    }
}
