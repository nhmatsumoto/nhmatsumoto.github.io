Heurísticas de Ordenação: QuickSort e MergeSort

Uma análise comparativa entre algoritmos de ordenação por comparação, focando em particionamento, estabilidade e complexidade assintótica.

Ordenar elementos é uma das tarefas mais fundamentais da computação. Embora o comando `.sort()` hoje seja uma abstração comum, entender o que acontece sob o capô (geralmente Timsort ou Introsort) é vital para otimizar sistemas em escala.

1. QuickSort: O Particionamento In-Place

O QuickSort utiliza a estratégia de **pivô**. Ele rearranja a lista para que elementos menores que o pivô fiquem à esquerda e maiores à direita.

flowchart TD A[Lista Desordenada] --> B{Escolher Pivô} B --> C[Particionar Around Pivô] C --> D[Esquerda < Pivô] C --> E[Direita > Pivô] D -->|Recursão| F[Ordenado] E -->|Recursão| F

2. MergeSort: A Estabilidade Garantida

Diferente do QuickSort, o MergeSort é **estável** (preserva a ordem de elementos iguais) e garante \(O(n \log n)\) mesmo no pior caso, sacrificando memória (\(O(n)\) de espaço auxiliar).

Complexidade Assintótica

Abaixo, a comparação de performance teórica:

Algoritmo Melhor Caso Caso Médio Pior Caso Estabilidade
QuickSort \(O(n \log n)\) \(O(n \log n)\) \(O(n^2)\) Não
MergeSort \(O(n \log n)\) \(O(n \log n)\) \(O(n \log n)\) Sim

Exemplo de Particionamento (TypeScript)

function partition(arr: number[], low: number, high: number): number {
    const pivot = arr[high];
    let i = low - 1;
    
    for (let j = low; j < high; j++) {
        if (arr[j] < pivot) {
            i++;
            [arr[i], arr[j]] = [arr[j], arr[i]]; // Swap
        }
    }
    [arr[i + 1], arr[high]] = [arr[high], arr[i + 1]];
    return i + 1;
}

Conclusão

Se a memória for escassa e o pior caso improvável, **QuickSort** vence. Se você precisa de estabilidade (ex: ordenar por nome e depois por data), **MergeSort** é a escolha correta.
