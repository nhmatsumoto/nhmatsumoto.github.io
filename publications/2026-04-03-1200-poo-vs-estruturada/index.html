Paradigmas: Programação Estruturada vs Orientada a Objetos

Uma análise profunda sobre a evolução do pensamento procedural para o modelo de objetos, com exemplos de acoplamento e coesão.

A escolha de um paradigma não é apenas sobre sintaxe, mas sobre como organizamos a complexidade. Enquanto a programação estruturada foca no fluxo de execução (procedimentos), a POO foca na interação entre entidades (objetos).

1. Programação Estruturada: O Fluxo Procedural

Baseada no Teorema da Programação Estruturada, qualquer programa pode ser escrito usando apenas três estruturas: sequência, decisão e iteração. Aqui, os dados são passivos e as funções são os agentes de transformação.

2. Programação Orientada a Objetos: Responsabilidade Distribuída

Na POO, mudamos o foco para quem realiza a ação. Os dados e as funções (métodos) são encapsulados em Objetos. Os quatro pilares fundamentais são: Abstração, Encapsulamento, Herança e Polimorfismo.

Métricas de Qualidade: O Cálculo de Acoplamento

A qualidade de um sistema pode ser medida matematicamente pela Instabilidade (\(I\)) de um componente, baseada em seu acoplamento aferente (\(Ca\)) e eferente (\(Ce\)):

$$I = \frac{Ce}{Ca + Ce}$$

Onde \(I=0\) representa um componente maximamente estável e \(I=1\) um componente maximamente instável.

Exemplo Comparativo (TypeScript)

// Abordagem Estruturada
function calcularArea(raio: number): number {
    return Math.PI * raio * raio;
}

// Abordagem POO
class Circulo {
    constructor(private raio: number) {}
    
    public getArea(): number {
        return Math.PI * this.raio * this.raio;
    }
}

Conclusão

Sistemas modernos raramente são puristas. O uso de **Programação Funcional** dentro de classes de **POO** é o padrão ouro para gerenciar estado e testabilidade de forma simultânea.
